# Controlled beta plan

Target cohort: 500–1,000 registered users only after core flows and capacity/cost assumptions are verified. Registration count is not concurrent load.

1. Internal testing with a few isolated accounts and devices.
2. Small invited cohort; resolve severe privacy, security, and reliability defects.
3. Expand gradually based on actual usage, costs, error rates, and feedback.

Before expansion: test account and session security, multi-account permissions, encryption, contacts, messaging, public audience controls, reporting/blocking, room access, voice if included, responsiveness, accessibility, load, backup recovery, monitoring, and rollback. Provide separate bug, suggestion, visual issue, and safety/security feedback routes. Do not collect passwords or unnecessary private conversation content.

No beta cohort, monitoring, or launch date is currently configured.
